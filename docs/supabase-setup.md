# Supabase Setup & Security Configuration Guide
## Patient Medical Report Management System

This document outlines the exact external configuration required to connect the system to Supabase Auth, PostgreSQL, and private Storage.

---

## 1. Supabase Project Creation & Credentials

1. Sign in to your [Supabase Dashboard](https://app.supabase.com) and create a new project.
2. Navigate to **Project Settings > API**:
   - Copy **Project URL** -> `SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_URL`
   - Copy **Project API Keys > `anon` `public`** -> `SUPABASE_ANON_KEY` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - Copy **Project API Keys > `service_role` `secret`** -> `SUPABASE_SERVICE_ROLE_KEY` *(Backend ONLY, never expose to frontend)*
   - Copy **JWT Settings > JWT Secret** -> `SUPABASE_JWT_SECRET` *(Backend ONLY)*

---

## 2. Phone Authentication (SMS OTP) Configuration

1. In Supabase Dashboard, navigate to **Authentication > Providers > Phone**.
2. Toggle **Enable Phone Provider** to `ON`.
3. Select and configure your SMS gateway:
   - **Twilio**: Provide `Twilio Account SID`, `Twilio Auth Token`, and `Twilio Message Service SID` / Phone Number.
   - **MessageBird / Vonage / Textlocal**: Supply the required provider API credentials.
   - **For Local Development / Testing**: In Supabase Dashboard under **Authentication > Providers > Phone**, you can configure test phone numbers with pre-set OTP tokens (e.g., `+919876543210` with token `123456`) to test live verification without incurring SMS costs.
4. **Rate Limiting & Abuse Prevention**:
   - Under **Authentication > Rate Limits**, ensure Phone OTP rate limits are enabled (default: 30 SMS per hour).
   - Backend in-memory rate limiting is also active (`backend/app/core/rate_limit.py`) for sensitive registration and recovery routes.

---

## 3. Redirect URLs & Site URL Configuration

1. In Supabase Dashboard, go to **Authentication > URL Configuration**:
   - **Site URL**: `http://localhost:3000` (or your production domain).
   - **Redirect URLs**: Add `http://localhost:3000/**`.

---

## 4. Applying Database Migrations

> **Important**: Do not run migrations against a live production database without a verified backup.

The migrations must be executed in order via the Supabase SQL Editor:
1. First, apply [`20261019000001_initial_schema.sql`](file:///c:/project/report_system/backend/supabase/migrations/20261019000001_initial_schema.sql):
   - Sets up initial tables (`users`, `patient_profiles`, `hospitals`, `hospital_staff`, `medical_reports`, `record_access_grants`, `emergency_access_logs`, `patient_recovery_requests`, `audit_logs`).
   - Enables Row-Level Security on all tables.
2. Second, apply [`20261019000002_security_audit_fixes.sql`](file:///c:/project/report_system/backend/supabase/migrations/20261019000002_security_audit_fixes.sql):
   - Adds unique database-level deduplication index (`idx_patient_profiles_phone_hash_unique`).
   - Installs immutability triggers preventing client tampering with `patient_id`, `user_id`, `verification_status`, and `role`.
   - Installs tamper-proof triggers ensuring `audit_logs` are strictly append-only.

---

## 5. Private Storage Bucket Setup

1. In Supabase Dashboard, go to **Storage > New Bucket**:
   - Name: `medical-reports`
   - **Public Bucket**: Disabled (`OFF`). All medical files must remain private.
2. File downloads are served strictly via short-lived signed URLs (300-second lifespan) generated by the backend API.
